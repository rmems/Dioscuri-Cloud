# [TRAIN] Artifact contract for checkpoints, logs, and metrics

**Override (2026-08-19):** Scope fully rewritten for **cloud AI model training setup**. Previous title: `[SAAQ] Cloud store + CPU validation pipeline for corinth-canal experiments`. SAAQ CPU store/validate on expired IBM/Oracle credits is superseded.

## Goal

Define the canonical object-storage layout and manifest fields for **training runs** (checkpoints, logs, metrics, run manifests). Downstream issues (#47, #53, #54, #59) implement against this contract.

## Scope

- Bucket prefix layout under `training/` (datasets, checkpoints, logs, metrics, manifests).
- Extend `docs/schemas/experiment-manifest.md` with training fields: `job_type=training`, `base_model`, `trainer`, `steps`, `checkpoint_uri`, `dataset_uri`.
- Document what is **never** in git: weights, secrets, private account IDs.

## Non-goals

- No SAAQ artifact migration from `corinth-canal/artifacts/`.
- No model weights in artifact buckets (stage to separate weights path at runtime).
- No GPU provisioning in this issue (documentation only).

## Deliverables

- [ ] `docs/training/artifact-layout.md` — canonical paths and naming
- [ ] `docs/schemas/experiment-manifest.md` — training field extensions
- [ ] `examples/training-run-manifest.synthetic.json` — public-safe example

## Acceptance criteria

- [ ] An agent can upload training outputs without inventing paths
- [ ] Layout is provider-neutral (same keys on S3 / Azure Blob)
- [ ] No secrets or weight files referenced in committed examples
